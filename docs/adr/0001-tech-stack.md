- **작성일:** 2026-05-26
- **작성자:** D-Connect 팀
- **관련 문서:** [PRD](../PRD.md), PM 요구사항 문서(2026-05-26)

## 컨텍스트

D-Connect는 8주(2026-05-14 ~ 07-08) 부트캠프 일정 내에 발표 시연 가능한 웹 프로토타입을 만드는 프로젝트다. 의사결정에 영향을 미치는 핵심 제약은 다음과 같다.

- **일정 압축** — 실제 개발은 3~5주차(2026-05-28 ~ 06-17) 약 3주에 집중되며, 6주차에는 안정화 + 발표 준비가 필요하다.
- **팀 규모** — 2~5명 소규모. 학습 부담이 적은 스택이 유리하다.
- **시연 안정성 최우선** — 2026-06-25 발표회 시연이 핵심 산출물. 인프라/배포 복잡도를 최소화해야 한다.
- **AI 통합** — SDGs 추천·콘텐츠 생성에 LLM을 사용하되, API 키 보호 + 호출 실패 시 mock 응답으로 흐름이 유지되어야 한다.
- **데이터 규모 작음** — 예시 기업 2~3건 + 데모 입력 수십 건 수준. 운영 트래픽은 고려 대상 아님.

PM 요구사항 문서에서 기술 스택은 사실상 명시되어 있으나(Next.js App Router / TypeScript / Prisma / SQLite), 본 ADR은 그 선택의 **컨텍스트·대안·트레이드오프**를 명문화해 이후 회고와 운영 단계 전환 시 근거 자료로 사용한다.

## 결정

다음 스택을 채택한다.

| 영역             | 채택                                  | 비고                                              |
|------------------|---------------------------------------|---------------------------------------------------|
| 프레임워크       | **Next.js (App Router)**              | 프론트엔드 + 백엔드 단일 코드베이스               |
| 언어             | **TypeScript**                        | 전 영역에서 사용                                  |
| ORM              | **Prisma**                            | schema-first + 마이그레이션 도구                  |
| DB               | **SQLite**                            | 파일 기반, 시연 환경 동봉 용이                    |
| AI 호출 경로     | **백엔드 API 경유**                   | 키 보호, 응답 정제, mock fallback 일원화          |
| AI 추천 방식     | **키워드 규칙 + LLM 결과 혼합**       | 설명 가능성 + 자연어 품질의 절충                  |
| 장애 대응        | **Mock 응답 fallback**                | AI 키 부재/호출 실패 시 동일 응답 형태 보장       |

## 대안

각 영역에 대해 검토한 대안과 채택하지 않은 이유.

### 풀스택 프레임워크

| 후보                                | 채택 여부 | 사유                                                                   |
|-------------------------------------|-----------|------------------------------------------------------------------------|
| **Next.js (App Router)**            | ✅ 채택    | 풀스택 단일, Route Handlers로 백엔드 일원화, 학습자료 풍부             |
| React + 별도 백엔드 (Express/Nest)  | ❌        | 2개 코드베이스 관리 부담, 8주 일정에 비효율                            |
| SvelteKit / Remix / Nuxt            | ❌        | 좋은 후보지만 팀 친숙도와 한국어 자료에서 Next.js 대비 열세            |
| Django / Rails                      | ❌        | 백엔드 중심, 프론트엔드 SPA 통합 부담                                  |

### DB

| 후보            | 채택 여부 | 사유                                                            |
|-----------------|-----------|-----------------------------------------------------------------|
| **SQLite**      | ✅ 채택    | 파일 하나로 끝, 시연 환경 동봉 가능, MVP 데이터 규모에 충분    |
| PostgreSQL      | ❌        | 운영 환경에는 적합하나 시연 셋업 부담 ↑                         |
| MySQL           | ❌        | 동일 사유                                                       |
| Supabase/Firebase | ❌      | 외부 의존 + 무료 한도 리스크, 시연 중 네트워크 의존 위험        |

### ORM

| 후보         | 채택 여부 | 사유                                                       |
|--------------|-----------|------------------------------------------------------------|
| **Prisma**   | ✅ 채택    | 타입 안전, 마이그레이션 도구, Next.js 호환 검증            |
| Drizzle      | ❌        | 가볍지만 마이그레이션 워크플로 미성숙                       |
| TypeORM      | ❌        | Prisma 대비 type safety 약함                                |
| Raw SQL      | ❌        | 타입 안전성 부족, AI 응답 구조 다루기 비효율                |

### 언어

| 후보            | 채택 여부 | 사유                                                        |
|-----------------|-----------|-------------------------------------------------------------|
| **TypeScript**  | ✅ 채택    | 타입 안전, AI 응답·DB 모델 같은 복잡 구조 다룰 때 유리      |
| JavaScript      | ❌        | 진입은 빠르나 협업·리뷰 비용 증가                            |

## 결과 및 트레이드오프

### 긍정 효과

- **빠른 개발 속도** — 단일 코드베이스, 풍부한 학습 자료, AI 코딩 도구(Claude Code/Codex) 호환성 우수.
- **시연/배포 단순화** — SQLite 파일을 함께 제공하면 발표 환경에서 별도 DB 인스턴스 불필요.
- **타입 안전성** — TypeScript + Prisma로 모델·API 경계가 강제됨. 리뷰 비용 절감.
- **장애 격리** — AI 호출을 백엔드에 가두어 키 노출 위험 차단 + 실패 시 mock으로 일관된 응답.

### 부정 효과 / 위험

| 위험                                          | 영향도 | 완화                                                                       |
|-----------------------------------------------|--------|----------------------------------------------------------------------------|
| **SQLite의 운영 한계** (동시 쓰기, 대용량)    | 운영 이관 시 ↑ | MVP 범위에서는 비이슈. 이후 PostgreSQL 마이그레이션 가능성을 Prisma schema로 열어둠 |
| **App Router의 짧은 안정성 역사**             | 중     | 안정된 패턴(server component + route handler)만 사용, 실험적 API는 회피     |
| **AI 호출 비용/지연**                         | 중     | 응답 캐시 + mock fallback + 호출 횟수 모니터링                              |
| **Prisma 마이그레이션과 SQLite의 일부 제한**  | 낮음   | 컬럼 변경 시 `prisma migrate` 동작 확인. 운영 이관 시 재검증 필요           |

### 모니터링 항목 (운영 단계 진입 시 추적)

- AI API 호출 성공률 / 평균 응답 시간
- mock fallback 발동 빈도
- DB 쿼리 지연 (Prisma Query Engine 로그)
