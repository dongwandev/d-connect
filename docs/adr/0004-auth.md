# ADR 0004: 인증 방식

- **상태:** Accepted
- **작성일:** 2026-05-28
- **작성자:** D-Connect 팀
- **관련 문서:** [PRD §3.0 / §6.1](../PRD.md), [ADR-0005 멀티테넌시](0005-multitenancy.md), [ADR-0001 기술 스택](0001-tech-stack.md)

---

## 컨텍스트

2026-05-28 플랫폼 전환 결정에 따라 회원가입·로그인을 MVP 범위에 포함한다 (PRD §6.1 변경 이력).

핵심 제약:

- **3주 개발 일정** 중 1주가 이미 경과 — 남은 일정에 인증 기능을 끼워 넣되 다른 기능 구현을 압박하지 않아야 한다.
- **발표 시연 대상**이 한국 사용자(부트캠프 심사위원, 지자체 담당자 등) 위주.
- **시연 안정성 우선** — 회원 인증이 시연 중 끊겨서는 안 된다.
- **App Router 친화적** — Next.js 16 App Router에서 1급 지원되는 라이브러리.

---

## 결정

**NextAuth.js v5 (Auth.js) + Prisma Adapter를 채택한다.**

### Provider 매트릭스

| Provider                | 채택 | 비고                                                            |
|-------------------------|------|-----------------------------------------------------------------|
| **이메일/비밀번호 (Credentials)** | ✅    | 주 회원가입 방식. bcrypt 해시 저장. 일반 웹사이트 표준 흐름  |
| **Kakao**               | ✅    | 간편 로그인. 한국 사용자 접근성 최상                            |
| **Google**              | ✅    | 간편 로그인. 보편적                                              |
| Email Magic Link        | ❌    | 2026-05-28 제외 결정 (사용자 결정). 향후 재검토 가능              |
| GitHub                  | ❌    | 개발자 친화적이나 시연 대상에 부적합                            |
| Passkey / WebAuthn      | ❌    | 좋지만 학습·구성 비용 ↑, 시기상조                                |
| 자체 이메일/비밀번호    | ❌    | bcrypt + 세션 + 이메일 인증 등 보안 코너케이스 부담              |

### 세션·저장

- **JWT Session** — NextAuth v5의 Credentials provider가 DB session과 호환되지 않아 JWT로 통일.
  - 트레이드오프: 강제 로그아웃이 어렵지만 MVP 수용 가능.
  - PrismaAdapter는 여전히 User/Account 행 생성에 사용.
- 세션 만료: 30일 (default).
- `secure: true` cookies (production).

### 라우트

- API: `src/app/api/auth/[...nextauth]/route.ts` — Auth.js 표준
- 페이지: `src/app/(auth)/login/page.tsx` — provider 버튼 노출
- Middleware: `src/middleware.ts` — 보호 경로(`/dashboard`, `/companies/*`, `/sdg-analysis/*`)에 세션 강제

### 환경 변수 (예정)

```
NEXTAUTH_SECRET=<랜덤 32+ byte>
NEXTAUTH_URL=http://localhost:3000

KAKAO_CLIENT_ID=
KAKAO_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

EMAIL_SERVER=smtps://...      # Magic Link용 (Resend / SMTP)
EMAIL_FROM=
```

전부 server 전용, 클라이언트에 절대 노출 금지.

## 결과 및 트레이드오프

### 긍정

- **표준 라이브러리** — 보안 패치·CSRF·세션 관리 등 안전망
- **Provider 교체 용이** — Kakao 등록 지연 시 Google·Magic Link로 시연 가능
- **DB session** — Prisma adapter가 User/Account/Session/VerificationToken 4개 모델을 자동으로 정의
- **App Router 통합** — server component에서 `auth()`로 세션 조회 간단

### 부정 / 위험

| 위험                                          | 영향도 | 완화                                                              |
|-----------------------------------------------|--------|-------------------------------------------------------------------|
| Kakao Developers 앱 등록 지연                 | 중     | Google + Magic Link만으로도 시연 가능. Kakao는 후순위 추가         |
| Magic Link SMTP 설정 부담                     | 중     | Resend 무료 계정 권장 (한도: 일 100건 시연 충분)                  |
| 외부 OAuth 장애 시 로그인 불가                | 낮음   | 시연 직전 Magic Link로 사전 로그인 + 세션 유지                    |
| 사용자 데이터 보호 (이메일 등)                | 중     | DB에만 저장, 응답 envelope에 노출 최소화, .env에 키 보관          |
| Provider 추가 시 OAuth callback URL 매번 등록 | 낮음   | 운영 단계 진입 시 production callback URL을 환경별로 분리         |

### 모니터링 항목

- 로그인 성공률 / 실패율 (provider별)
- 세션 만료로 인한 재로그인 빈도
- Magic Link 클릭률 (이메일 발송 후)
