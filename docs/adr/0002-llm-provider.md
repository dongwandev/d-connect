# ADR 0002: LLM Provider 선정

- **상태:** Accepted
- **작성일:** 2026-05-26
- **작성자:** D-Connect 팀
- **관련 문서:** [PRD](../PRD.md) (§3.2, §3.4, §5.3), [ADR-0001](0001-tech-stack.md) (§추후 결정)

---

## 컨텍스트

D-Connect의 핵심 기능 중 **SDGs 목표 추천**(PRD §3.2)과 **공공홍보 콘텐츠 생성**(PRD §3.4)은 LLM 호출에 의존한다. ADR-0001에서 추후 결정 항목으로 미뤘던 LLM Provider를 본 ADR에서 확정한다.

선택에 영향을 미치는 핵심 요구는 다음과 같다.

- **한국어 공공홍보 톤** — 광고성·과장·검증되지 않은 수치를 회피해야 한다 (PRD §5.3).
- **Mock fallback 호환** — API 키 부재나 호출 실패 시 동일한 응답 형태로 흐름이 이어져야 한다 (PRD §5.2).
- **3주 통합 일정** — 2026-05-28 ~ 06-17 내에 통합·안정화가 끝나야 한다.
- **발표 시연 안정성** — 2026-06-25 발표회 시연에서 끊김·실패가 없어야 한다.
- **AI 개발 도구와의 일관성** — 개발에 Claude Code/Codex를 사용하므로 프롬프트 패턴 회고를 같은 모델 계열에서 일관되게 진행할 수 있으면 유리하다.

## 결정

**Anthropic Claude API를 LLM Provider로 채택한다.**

### 모델 매트릭스

| 용도                                | 모델                  | 비고                                              |
|-------------------------------------|-----------------------|---------------------------------------------------|
| SDGs 분석 + 콘텐츠 생성 (기본)      | **Claude Sonnet 4.7** | 균형 잡힌 품질/비용. MVP 대부분 호출의 기본 경로  |
| 빠른 키워드 분류 / 짧은 요약 (보조) | Claude Haiku 4.7      | 저지연·저비용. SDGs 사전 분류 단계 등에서 선택 사용 |
| 고난도 작성 (옵션)                  | Claude Opus 4.7       | MVP에서는 기본 사용하지 않음. A/B 비교 시 사용     |

### SDK / 통합 방식

- TypeScript SDK: **`@anthropic-ai/sdk`**
- 모든 호출은 **Next.js Route Handler 경유** — ADR-0001의 "AI는 백엔드 API 경유" 원칙 준수
- 모델 ID는 환경변수(`LLM_MODEL_DEFAULT`, `LLM_MODEL_FAST`)로 분리해 교체 용이성 확보
- **Prompt caching** — SDGs 정의 + 공공홍보 톤 가이드 + few-shot 예시는 시스템 프롬프트로 묶어 캐시 적용
- 구조화 응답이 필요한 경우 **Tool Use(JSON 스키마)** 사용

### 운영 가드

| 항목         | 정책                                                              |
|--------------|-------------------------------------------------------------------|
| API 키       | 서버 환경변수 `ANTHROPIC_API_KEY`로만 관리. 클라이언트 노출 금지   |
| Mock fallback | 키 부재 / 호출 실패 / 타임아웃 시 동일 응답 스키마로 모킹 응답 반환 |
| 타임아웃     | 30초. 초과 시 mock으로 폴백                                        |
| 재시도       | SDK 기본 정책 사용 (지수 백오프, 최대 2회)                         |
| 응답 검증    | JSON 스키마 검증(zod 등) 후 클라이언트 전달                         |

## 대안

| 후보                          | 채택 여부 | 사유                                                                  |
|-------------------------------|-----------|-----------------------------------------------------------------------|
| **Anthropic Claude**          | ✅ 채택    | 공공홍보 톤 적합, AI 개발 도구와 동일 계열, nuanced 한국어 분석 강점   |
| OpenAI GPT (4o / 4o-mini)     | ❌        | Structured Outputs(JSON Schema 강제)는 매력적이나, 톤·일관성에서 Claude가 D-Connect 요구에 더 부합 |
| 다중 Provider 추상화 계층     | ❌        | 3주 개발 일정에 오버스펙. mock fallback이 일부 추상화 효과 제공         |
| 오픈소스 모델 셀프 호스팅 (Llama 등) | ❌  | 인프라 부담, 시연 환경 위협, 한국어 품질 변동성                        |
| 단일 호출 + Embedding RAG     | ❌        | MVP의 SDGs는 4개 + 키워드 매핑이라 RAG 도입은 시기상조                 |

## 결과 및 트레이드오프

### 긍정 효과

- **톤 정합성** — 시스템 프롬프트만으로도 광고성·과장 회피가 잘 지켜지는 경향.
- **개발 도구 일관성** — Claude Code/Codex 사용 시 같은 모델 계열에서 프롬프트 패턴·실패 모드 회고 일관.
- **Prompt caching** — 시스템 프롬프트 비용 절감 + 응답 latency 단축.
- **모델 교체 용이** — 환경변수로 Sonnet ↔ Haiku 전환 가능, 비용·속도 튜닝 단순.

### 부정 효과 / 위험

| 위험                                       | 영향도 | 완화                                                              |
|--------------------------------------------|--------|-------------------------------------------------------------------|
| Structured Output 강제력이 OpenAI 대비 약함 | 중     | Tool Use(JSON 스키마) + zod 응답 검증 + 실패 시 재시도 / mock      |
| 호출 latency (콘텐츠 생성 단계)             | 중     | 스트리밍 응답으로 체감 개선, 콘텐츠 화면에 점진 표시               |
| API 비용                                   | 낮음   | MVP 규모(예시 기업 2~3 + 데모) 이내. Haiku 폴백 옵션 보유          |
| 모델 deprecation                           | 낮음   | 모델 ID를 환경변수로 분리, SDK 버전 업데이트 시 회귀 테스트         |
| 한국어 출력의 미세한 어색함                 | 낮음   | few-shot 예시 + 검수 가능한 초안 정책(PRD §5.3) — 사람 수정 전제   |

### 모니터링 지표 (운영 시)

- 호출당 응답 시간 (p50 / p95)
- 호출 실패율 + mock fallback 발동률
- 모델별 토큰 사용량 (월별)
- 응답 스키마 검증 실패 비율
