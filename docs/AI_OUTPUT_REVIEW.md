# AI 출력 검증 가이드 (PRD §5.3 톤 가드)

> 발표 시연 전 AI 출력을 sampling으로 점검하기 위한 가이드. 시연자·QA·디자인 리뷰 단계에서 모두 참고한다.

---

## 1. 검증 기준 — PRD §5.3 콘텐츠 품질

| 항목 | 기준 |
|---|---|
| 광고성·과장 표현 | "최고의", "유일한", "혁신적인" 등 최상급/유일성 단어 미사용 |
| 검증되지 않은 수치 | 입력 활동 설명에 명시된 수치만 인용. 추측 수치 0건 |
| 단정적 효능 주장 | "~한 효과가 있다" 대신 "~에 기여한다", "~할 수 있다" 표현 |
| 허위 사실 | 입력에 없는 수상·인증·협력 기관·매출 등 미생성 |
| 출력 형식 | 항상 tool calling으로 구조화된 JSON 반환 |
| 한국어 톤 | 공공기관 보도자료·카드뉴스 ~합니다체 (SNS는 ~해요체 허용) |

## 2. Sampling 절차 (시연 전 권장)

### 2.1 환경 준비
```bash
# OpenAI API 키 확인 (.env)
grep OPENAI_API_KEY .env   # 비어 있으면 mock으로만 동작

# demo 계정 보장 (비파괴 — 기존 기업 데이터 유지, #107)
pnpm db:seed

# dev 또는 production 모드로 서버 실행
pnpm dev   # 또는 pnpm build && pnpm start
```

### 2.2 SDG 분석 sampling — 3건 이상 권장
1. demo 계정으로 로그인 → 등록된 기업(유클리드소프트) 진입
2. **"다시 분석"** 클릭을 2~3회 반복 — 점수·근거의 변동 폭 확인
3. SDG 매칭 카드의 `rationale` (근거 문장)과 `keywords` 확인
4. (선택) **"+ 새 기업 등록"**으로 다른 기업을 입력하고 분석
5. **샘플링 후 정리**: 표본으로 만든 분석·콘텐츠는 확인 후 삭제해 시연 데이터를 깨끗하게 유지

### 2.3 콘텐츠 생성 sampling — 4가지 유형 각 2건 이상
- 분석 페이지에서 SNS_POST · CARD_NEWS · SHORT_VIDEO_SCRIPT · POSTER 모두 생성
- **세부 설정을 다양화** — 대상 SNS(특히 X의 280자 제한)·비율·카드 수·이미지 스타일·추가 요청 조합을 바꿔가며
- 같은 조합을 한 번 더 생성해 변동 폭 확인

## 3. 위반 사례 체크리스트

각 sampling 결과에 대해 아래 체크리스트로 점검. 하나라도 ✗면 위반 후보.

### 3.1 광고성·과장 표현
- [ ] **최상급/유일성** 단어 사용 안 함 (최고, 최초, 유일, 독보, 압도, 역대급, 전례 없는, 선도적)
- [ ] **과장 수식어** 사용 안 함 (혁신적인, 획기적인, 단연, 초유의)
- [ ] **강한 권유** 사용 안 함 (지금 바로, 놓치면 후회 — 콘텐츠에 한정)

### 3.2 수치 환각
- [ ] 결과에 등장하는 모든 수치(예: "18,000개", "412명", "70%")가 입력 활동 설명에 **그대로** 있음
- [ ] 입력에 없는 통계·비율·인원수·금액·기간이 추가되지 않음

### 3.3 단정 vs 가능성
- [ ] "~한 효과가 있다", "~를 해결한다", "~을 보장한다" 패턴 없음
- [ ] "~에 기여한다", "~할 수 있다", "~기대된다" 같은 가능성 표현 사용

### 3.4 허위 사실
- [ ] 수상 이력·인증·협력 기관·매출 같은 미입력 정보가 등장하지 않음
- [ ] 기업명·지역·업종이 입력과 일치 (오인 표기 없음)

### 3.5 톤
- [ ] 본문이 ~합니다체 (또는 SNS의 ~해요체)
- [ ] 영어·중국어 혼용 없음 (정식 용어를 위한 약어/괄호 표기는 허용)

## 4. 위반 발견 시 대응

### 4.1 단발성 위반 (1~2건)
- 분석/생성 다시 실행 — 모델이 일관되지 않게 위반할 수 있음
- 그래도 같은 위반이 반복되면 4.2로 escalation

### 4.2 패턴성 위반 (3건 이상)
1. **시스템 프롬프트 보강** — `src/server/ai/prompts/sdg-analysis.ts` 또는 `content-generation.ts`의 가드 섹션에 위반 패턴 추가
2. **재배포 후 다시 sampling** — 위반 빈도가 줄어드는지 확인
3. 그래도 안 되면 **출력 후 필터** 검토:
   - 광고성 단어 사전(`AD_PHRASES`)을 만들고 응답에서 발견되면 자동 재생성
   - 또는 사용자 UI에 "광고성 표현이 감지되었어요" 경고 (편집 유도)

### 4.3 시연 직전 발견
- 시연용 콘텐츠는 미리 한 번 생성·편집해 두고 그 결과만 시연
- 시연 중 라이브 생성은 가능한 한 시드 데이터 기반으로 (예측 가능한 입력)

## 5. 자동화 (향후)

### LLM-as-judge (별도 PR)
- Anthropic 또는 OpenAI 모델로 출력을 평가
- 위반 점수 0~10 산출
- CI 단계에 통합 가능

### 키워드 기반 사후 필터 (mock 수준 보완)
- `src/server/ai/post-filter.ts` 같은 모듈에서 본문 검사
- 발견된 광고성 표현을 응답에 메타데이터로 포함
- UI에서 경고 배지로 표시

이 둘은 발표 시연 마감 이후 단계.
